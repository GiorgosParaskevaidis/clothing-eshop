## Schema W11

| Πίνακας | Σχέσεις / εγγυήσεις |
|---|---|
| schema_migrations | PK version, SHA-256 checksum, applying/applied/failed, UTC εφαρμογής |
| users | PK id UUID N, UNIQUE normalized_email και normalized_user_name, salted password hash, enabled/email_confirmed, stamps, failure counter/lockout, MFA flag, UTC timestamps |
| roles | PK id, UNIQUE normalized_name· Customer/Admin ως reference data |
| user_roles | Composite PK user_id/role_id, FKs users/roles |
| user_sessions | PK hash τυχαίου nonce, FK users, scope/amr/stamp, expires/revoked UTC, indexes user/expiry |
| user_action_tokens | PK id, UNIQUE token hash, FK users, purpose/stamp/expiry/used/attempts/target_email, indexes user-purpose/expiry |
| user_mfa | PK/FK user_id, προστατευμένο key μέσω Data Protection, τελευταίο αποδεκτό TOTP interval |
| user_recovery_codes | PK user_id/code_hash, FK users, consumed UTC· 10 κωδικοί μιας χρήσης |
| auth_rate_windows | PK SHA-256 purpose/normalized target, atomic counter, window UTC/index |
| audit_log | Actor id, action/entity id και UTC· χωρίς passwords, email payloads, session nonces ή action tokens |

Όλοι οι νέοι πίνακες είναι InnoDB. Δεν γίνονται cascade deletes χρηστών/παραγγελιών. Email γίνεται trim και Unicode NFC, έπειτα Identity uppercase normalization· δεν αφαιρούνται dots ή +suffixes. Τα identity ids δεν αλλάζουν αν αλλάξει email. Tokens και recovery codes αποθηκεύονται μόνο ως hashes. Το MFA secret κρυπτογραφείται με κλειδιά εκτός SQL.

Το migration εργαλείο χρησιμοποιεί μία ήδη επιλεγμένη βάση και ξεχωριστά DDL privileges. Δεν γίνεται runtime production migration ή seed. Ο λεπτομερής έλεγχος baseline προηγείται της υιοθέτησης υπαρχόντων πινάκων. Checksum mismatch ή ατελής εφαρμογή σταματούν τις επόμενες αλλαγές. Δεν επιχειρείται αυτόματο rollback MariaDB DDL.

## HTTP contracts W12

Όλα τα routes αρχίζουν με /api, JSON requests, κεφαλίδα X-Store-Request: 1 για mutations. Σε Auth:Enabled=true απαιτείται και X-CSRF-Token από GET /api/security/csrf με το antiforgery cookie του ίδιου browser. Το frontend μιλά σε κοινό origin μέσω του υπάρχοντος Next.js proxy· CORS δεν χρειάζεται με αυτή τη διάταξη.

| Route / method | Input | Απάντηση / πρόσβαση |
|---|---|---|
| GET /auth/config | — | enabled, δημόσιο |
| GET /security/csrf | — | token/required, HttpOnly antiforgery cookie |
| POST /auth/register | email, password, displayName | 202 γενικό μήνυμα και προστατευμένο HttpOnly registration cookie 24 ωρών, Customer role από server, απαιτεί email verification |
| POST /auth/login | email, password | 200 email/displayName και Customer cookie ή γενικό 401 |
| GET /auth/session | — | id/email/displayName/emailConfirmed/scope, Customer policy |
| POST /auth/logout | — | 204, ανάκληση τρέχοντος Customer session |
| POST /auth/verify-email | token | 200 signedIn ή 400, μία χρήση, 24 ώρες· Customer cookie μόνο με έγκυρο registration context |
| POST /auth/resend-verification | email | 202 γενικό μήνυμα |
| POST /auth/forgot-password | email | 202 γενικό μήνυμα |
| POST /auth/reset-password | token, password | 204 ή 400, 15 λεπτά, ανάκληση όλων των sessions |
| POST /auth/password/change | currentPassword, newPassword | 204, Customer, ανάκληση όλων των sessions |
| POST /auth/email/change | email, password | 202, Customer, link στο νέο email και ειδοποίηση στο παλιό |
| POST /auth/email/confirm | token | 204 ή 400, 30 λεπτά, ανάκληση sessions |
| POST /admin/login | email, password | challengeToken/requiresMfa/requiresSetup, χωρίς πλήρες admin cookie |
| POST /auth/admin/mfa/setup | token | key/authenticatorUri, έγκυρο setup challenge 5 λεπτών |
| POST /auth/admin/mfa/verify | challengeToken, code | Admin cookie μόνο μετά TOTP/recovery· νέα recoveryCodes κατά enrollment |
| POST /auth/admin/reauth | password | challengeToken 5 λεπτών, Admin policy |
| POST /auth/admin/recovery-codes | challengeToken, code | 10 νέοι recoveryCodes, password + MFA, ακύρωση προηγουμένων |
| POST /auth/admin/mfa/reset | challengeToken, code | νέο setup challenge, password + MFA, ανάκληση όλων των admin sessions |
| POST /auth/admin/password/change | currentPassword, newPassword | 204, Admin policy, ανάκληση sessions |
| POST /auth/admin/email/change | email, password | 202, Admin policy, ίδιο ασφαλές confirmation contract |

Τα υπάρχοντα /admin/session, /admin/logout, /admin/products, /admin/stock/{id}, /admin/orders, /admin/orders/{id}/fulfill και /admin/subscribers προστατεύονται από την ίδια Admin policy. Το POST /admin/login είναι το μοναδικό δημόσιο password βήμα και δεν δίνει πλήρη πρόσβαση πριν MFA.

| Χρήστης | Customer routes | Admin routes | Guest checkout |
|---|---|---|---|
| Ανώνυμος | Μόνο δημόσιες auth ροές | Password/MFA challenge μόνο | Ναι |
| Customer | Δικό του session/security | Απορρίπτεται, ανεξάρτητα από το frontend | Ναι |
| Admin πριν MFA | Καμία πλήρης admin ταυτότητα | Μόνο έγκυρο challenge | Ναι |
| Admin μετά MFA | Απαιτεί ξεχωριστό Customer role/cookie | Admin scheme + role + amr=mfa | Ναι |

Ο admin δημιουργείται μόνο μέσω ελεγχόμενου CLI bootstrap. Το νέο database auth αποκλείει το παλιό demo scheme/hash. Auth:Enabled=false διατηρεί το ξεχωριστό Development/Preview demo χωρίς customer accounts. Το Production αρνείται να ξεκινήσει με αυτό το flag.

## Κανόνες ασφάλειας

- Απόφαση χρήστη 14/10/2026: νέος κωδικός 8–128 Unicode χαρακτήρων, με τουλάχιστον ένα κεφαλαίο, ένα μικρό, έναν αριθμό και ένα σημείο στίξης ή σύμβολο. Το κενό δεν μετρά ως σύμβολο. Ίδιος κανόνας σε εγγραφή, επαναφορά, αλλαγή κωδικού και CLI bootstrap· οι υπάρχοντες κωδικοί εξακολουθούν να λειτουργούν στη σύνδεση. Identity PBKDF2 hasher 210.000 iterations, αυτόματο rehash. Μικρή ενσωματωμένη common-password λίστα και υποστήριξη ιδιωτικού SHA-256 dataset· πλήρες ενημερωμένο dataset απαιτείται πριν production.
- Host-only HttpOnly cookies: Customer Lax/24 ώρες, Admin Strict/2 ώρες, χωρίς sliding/persistent remember-me. Secure και __Host- ονόματα εκτός Development. Server validation nonce/stamp/role/enabled/expiry σε κάθε προστατευμένη κλήση.
- Logout ανακαλεί το τρέχον session. Αλλαγή/reset password, επιβεβαιωμένη αλλαγή email, MFA reset και αλλαγή ρόλου ανακαλούν όλα τα sessions. Απενεργοποίηση μέσω Identity store αλλάζει security stamp.
- Login/MFA/reauth: 5 requests/min/IP. Register/link operations: 20/min/IP και 5/hour/normalized target/purpose στη βάση. Πέντε λάθος password/MFA προσπάθειες κλειδώνουν λογαριασμό για 15 λεπτά· το διάστημα δεν παρατείνεται από νέες προσπάθειες όσο είναι κλειδωμένος. Retry-After σε 429. Τα αυξημένα όρια του isolated harness επιτρέπονται μόνο σε Development· ο τελικός έλεγχος τρέχει ξανά με τα κανονικά όρια.
- MFA TOTP 6 ψηφίων/30 seconds, παράθυρο ±1 interval και προστασία replay στη SQL συναλλαγή. Recovery redemption είναι atomic. Challenge expiry/attempt cap/stamp/ρόλος επαληθεύονται από server.
- Origin πρέπει να ισούται με Store:PublicUrl origin όταν υπάρχει. Οι CLI clients χωρίς Origin χρειάζονται επίσης CSRF cookie/token και X-Store-Request. Εξαιρείται μόνο το Stripe webhook που έχει δική του υπογραφή.
- Auth σώμα έως 16 KiB, λοιπά requests έως 1 MiB, με όριο Kestrel. Generic auth errors, no-store και nosniff. Action links χρησιμοποιούν fragment, χωρίς token σε query/referrer· ο browser αφαιρεί το fragment από τη γραμμή διεύθυνσης.
- Forwarded headers αγνοούνται εκτός ρητών Proxy:KnownAddresses. Η λίστα δεν εμπιστεύεται αυτόματα loopback. Δοκιμάστηκε απόρριψη spoofing χωρίς trusted proxy· η πραγματική production αλυσίδα edge → Next → API παραμένει W50.

## Οθόνες και λειτουργία

Οι /account/login, register, verify-email, forgot-password, reset-password και /account είναι ξεχωριστές σελίδες. Το /admin χρησιμοποιεί focused components για sign-in/enrollment/recovery/security. Tokens/passwords δεν αποθηκεύονται σε localStorage. Account/admin έχουν noindex και no-referrer metadata. Δεν εισάγεται νέο framework ή δεύτερος μηχανισμός authentication στο Next.js.

Στις 14/10 βελτιώθηκε η εγγραφή: μετά το Confirm email γίνεται αυτόματη σύνδεση και μετάβαση στο /account στον ίδιο browser. Το RegistrationContinuation χρησιμοποιεί time-limited Data Protection cookie, δεσμευμένο σε user id/security stamp, χωρίς password. Όλες οι accepted εγγραφές, και οι duplicate, λαμβάνουν ίδιο τύπο opaque cookie· μόνο το context μιας πραγματικής νέας εγγραφής μπορεί να ταιριάξει. Μετά από έγκυρη επιβεβαίωση το cookie αφαιρείται και δημιουργείται νέο session id/amr=email. Άλλος browser, αλλοιωμένο/ασύμβατο context, ήδη confirmed account, ενεργό διαφορετικό Customer session, lockout, MFA ή Admin role δεν προκαλούν αυτόματη σύνδεση. Το frontend μεταφέρει τότε στο login?verified=1. Αλλαγή email απαιτεί νέα σύνδεση και admin εξακολουθεί να απαιτεί MFA.

Σχετικές πηγές: [Microsoft — Time-limited Data Protection](https://learn.microsoft.com/en-us/aspnet/core/security/data-protection/consumer-apis/limited-lifetime-payloads), [OWASP — Login CSRF και νέα session identifiers](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).

Στη συγκεκριμένη τοπική εγκατάσταση έγιναν migrations και νέο admin bootstrap στην thesamenot_test μετά από ιδιωτικό backup και επιτυχή επαναφορά σε προσωρινή βάση. Τα fingerprints των έξι εμπορικών πινάκων παρέμειναν ίδια. Η βάση έχει πλέον 16 πίνακες, συμπεριλαμβανομένων του migration ledger και identity.

Το ignored appsettings.Local.json έχει Auth:Enabled=true, Database:Initialize=false και μόνιμα .local/auth-keys / .local/auth-mail directories. Τα νέα credentials είναι μόνο στο [.local/auth-admin-access.txt](D:/Projects/clothing-eshop/.local/auth-admin-access.txt). Το ενεργό Debug process δεν διακόπηκε: χρειάζεται νέο F5 από Visual Studio και authenticator enrollment από τον ιδιοκτήτη. Η Release δοκιμή στην ίδια configuration δέχτηκε το νέο password και απέκλεισε admin πρόσβαση πριν MFA.

Το ιδιωτικό [.local/phase1-local-activation.json](D:/Projects/clothing-eshop/.local/phase1-local-activation.json) καταγράφει τη θέση backup/verification. Για νέα εγκατάσταση ή άλλον προσωπικό admin ισχύει το [StoreMaintenance README](D:/Projects/clothing-eshop/tools/StoreMaintenance/README.md). Τα destructive integration fixtures συνέχισαν να χρησιμοποιούν αποκλειστικά τις δικές τους προσωρινές βάσεις.

Στις 14/10 ενεργοποιήθηκε και ελέγχθηκε πραγματικό Brevo SMTP από την τοπική εφαρμογή: TLS/authentication, verification email Delivered και επιβεβαιωμένη παραλαβή από τον ιδιοκτήτη. Το From αντικαθίσταται με brevosend.com λόγω Gmail χωρίς ιδιόκτητο domain. Η background ουρά είναι περιορισμένη και μη μόνιμη· durable outbox/retries είναι W43. Production εξακολουθεί να απαιτεί πιστοποιημένο domain/αποστολέα, προστατευμένο μόνιμο key ring, HTTPS και blocklist. Certificate/key rotation/restore, Stripe redirects και trusted proxy/load tests παραμένουν χωριστά εκκρεμή.
